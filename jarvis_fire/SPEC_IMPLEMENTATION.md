# ДЖАРВИС FIRE — обязательные требования к реализации

Статус: рабочий контракт реализации по согласованному ТЗ v1.0. Все сборки до проверки сквозного сценария помечаются «УЧЕБНЫЙ ПРОТОТИП».

## Основная архитектура
- Диспетчерская программа Windows, мобильное приложение РТП Android/iOS, общий защищённый сервер и база данных.
- Диспетчер вручную создаёт вызов и вручную выбирает адресатов.
- Сервер регистрирует вызов, направляет уведомления выбранным адресатам.
- РТП подтверждает получение вызова, вручную изменяет статусы, отправляет сообщения и фотографии.
- **Закрыть вызов может только диспетчер.** Все изменения сохраняются в неизменяемом журнале аудита.
- При отсутствии связи мобильное приложение сохраняет действия локально и синхронизирует после восстановления.
- Отображение карты Ставрополя и Ставропольского края; голосовой помощник; архив; формирование документов Word.

## Утверждённый интерфейс
- Общая палитра: тёмный графит, красные акценты, крупные контрастные элементы.
- Windows/веб-диспетчерская: **активные вызовы слева, подробности выбранного вызова справа**.
- Мобильный главный экран: **ВЫЗОВ, ОБЪЕКТ, КАРТА, ПОМОЩНИК, ЖУРНАЛ, ФОТОГРАФИИ**.
- Не добавлять вымышленные элементы интерфейса или оперативные данные как будто они реальные.

## Данные объектов и водоисточников — ПОСЛЕДНИЙ ЭТАП
- Здания привязывать только по адресу.
- Водоисточники импортировать из Excel.
- Карточка объекта: отдельный Word-документ с полной информацией, планом местности и поэтажным планом.
- **Не отвлекаться на разработку реестров объектов и водоисточников до реализации основного цикла вызова.**

## Очередность работ
1. Схемы данных, серверный API, роли, аутентификация, аудит.
2. Сквозной сценарий вызова и назначения адресатов.
3. Windows-диспетчерская (левая колонка вызовов, правая карточка вызова).
4. Android/iOS РТП (6 утверждённых разделов, уведомления, ручные статусы, офлайн-очередь).
5. Карта, сообщения, фото, архив, Word-документы, голосовой помощник.
6. Только затем импорт водоисточников из Excel и объектные карточки Word.
7. Интеграционные тесты, безопасность, развёртывание, сборки EXE/APK.

## Критерии готовности
- Программа не называется «готовой», пока не проверен сквозной сценарий Windows → сервер → Android → сервер → Windows.
- Сборка EXE/APK сама по себе не означает выполнения ТЗ.
- Для боевого использования потребуются проверка безопасности, отказоустойчивости, разграничения доступа и испытания в организации.
